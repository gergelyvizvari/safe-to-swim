## Integrated source

The shared `ea-brighton-samples` adapter retrieves one bounded EA latest-samples
collection every six hours through the existing `/api/source-checks` collector.
Each site's binding matches both the official ID and sampling coordinates.
The response currently also includes a historical Newhaven record; it is excluded
because it is outside the verified active-site allowlist. Pagination, duplicates,
withdrawn/replaced records, missing counts and unrecognised qualifiers fail closed.
Last valid payloads remain available with stale status after collection failure.

The panel shows E. coli and intestinal enterococci colony counts per 100 ml,
retaining `<`, `=` and `>` qualifiers. EA has not assigned classifications to
individual samples since 2015. No pass/fail or swimming clearance is inferred.
The current samples are from 10 or 14 September and all exceed the conservative
seven-day sample age used here. Checking the feed does not reset sample age.
Provider date-times lack UTC offsets; only the provider's calendar date is shown.
Ageing uses the earliest possible London date boundary (UTC midnight minus one
hour), rather than inventing a precise sampling instant. This can age winter
samples up to an hour early. `published_at` for the shared feed remains null:
retrieval time is not a measurement publication timestamp.

Official pollution forecasts/incidents are accessible on each linked EA profile.
They are NOT imported as current observations: `normal` risk alone would miss
other advice-against-bathing conditions, and risk expiry offset semantics still
need verification. Southern Water discharge events and measured sea temperature
are not added in this batch; existing per-location Open-Meteo models remain.

## Activation and verification

After deploying the adapter, run `scripts/import-brighton-expansion.mjs` with the
existing server environment, first dry-run then `--apply`. This uses only the
configured Supabase project. It validates all identities before writing, inserts
the shared source and targets before bindings, and never alters unrelated rows.
Each REST request is atomic; the multi-table process is resumable, not one SQL
transaction. Orientation writes compare original metadata to avoid overwriting
concurrent edits. The SQL orientation import is also retained as an alternative.
The existing collector claims newly inserted sources automatically.

Validation: 114 tests, lint, production build; 101 shoreline bearings reproduced
against retained versioned geometry. Local UI inspected with live EA values,
old-data notice, date, qualifiers and the exact official source link.
